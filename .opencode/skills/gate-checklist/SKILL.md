# Gate проверяемости (до старта волны)

Режим `verifier` C. Цель — убедиться, что работы можно запускать и проверять. При любом провале — `gate_failed` и эскалация **до начала работ**: ветка волны не создаётся, задачи не запускаются.

## Чек-лист
1. **Проверяемость задач:** у каждой `T-*` есть воспроизводимые `Как проверить` и проверяемые `Готово, если`.
2. **Сценарий волны:** есть сценарий `architect` — общие проверки + проверки добавленных/изменённых механик; либо явное «достаточно сборки и запуска».
3. **База плана (PI-001):** базовый commit плана совпадает с целевой базой волны. Перечислить новые файлы/артефакты базы, которые затрагивают сценарий/ownership, и подтвердить, что они отражены в плане/ownership/проверках. При расхождении — `gate_failed`.
4. **Полнота ownership:** новый файл базы, который может понадобиться задаче, либо включён в `Владеет файлами`, либо явно «не трогать».
5. **Launch-план:** группы параллельности без пересечений ownership, порядок/зависимости, refs для `orchestrator`.
6. **Окружение:** проверить и зафиксировать доступность dotnet, TTY/`script` (для Spectre CLI), remote/`gh`, CI. Ограничения — как ограничения с доказательствами, не как успех.
7. **Трассировка:** `Покрывает` ссылается на существующие `FS-*`/`§…`/K/B/D.

## Результат
- Всё выполнено → `gate_passed` (refs на план/сценарий/launch-план).
- Пробелы → `gate_failed` с refs на конкретные пункты; доработка `architect` (при необходимости `analyst`), затем повторный gate.
- Каждый исполнитель перед стартом своей части также проверяет проверяемость своего объёма и эскалирует/останавливается при проблемах.
