# Process retro (PI-*)

Журнал: `docs/projectDocs/process-improvement-log.md`. Владелец: `process-master`. Не путать с техдолгом (`TD-*`).

## Правила
- **Обратной силы нет:** журнал ведётся для новых волн/мер; прошлые не пересобираются; пробелы данных фиксировать явно.
- **Детерминизм vs сложность:** каждая мера имеет проверяемый критерий эффекта и оценку влияния на сложность; меры без эффекта упрощаются/откатываются.
- **Циклы:** если мера вернула ранее устранённую проблему — фиксировать `regressed/cycle` со ссылкой на исходную запись и волну.
- **Замыкание петли:** каждую прошлую `PI-*` со статусом `proposed` переводить в `applied`/`verified`/`regressed` либо явно откладывать с причиной (не оставлять «висеть»).

## Формат записи
```md
## PI-### — <краткое имя>
- **Статус:** proposed | applied | verified | regressed | observed | rolled-back | wontfix
- **Волны/контекст:** Wave N, <T-* / refs>
- **Проблема (факты):** …
- **Причина/гипотеза:** …
- **Мера:** … (ссылки на файлы процесса/шаблонов/агентов/скиллов)
- **Критерий проверки эффекта:** … (что наблюдаем в следующих волнах)
- **Влияние на сложность:** низко/средне/высоко (+ обоснование)
- **Результат/наблюдение:** … (волна, факт; «недостаточно данных» — допустимо с пояснением)
- **Ссылки:** `wave-*-report.md`, task-отчёты, коммиты/MR/ветки, связанные PI-*
```

## Выход
- Обновлённый `process-improvement-log.md`.
- Вклад для `## Ретро процесса` в `wave-*-report.md` (handoff/ref); канонический коммит отчёта делает `verifier`.
