# Технический долг (операционный бэклог находок)

Этот файл фиксирует **находки вне текущей задачи**, которые могут «выстрелить позже» (риски, расхождения, латки, архитектурные компромиссы). Он отдельно от:
- `docs/projectDocs/todo.md` — утверждённые исполняемые задачи/карточки `T-*` (план waves);
- `docs/gameDocs/featureBacklog.md` — игровые идеи и механики.

Активный список в этом файле должен содержать в основном записи со статусами `open` и `planned`. Закрытые записи (`done`, `wontfix`) периодически переносятся в `docs/projectDocs/tech-debt-archive.md` или очищаются по решению `architect`/`orchestrator`/`docs-maintainer` (обычно при закрытии волны, подготовке wave-report или планировании следующей волны) с сохранением трассируемости (`TD-*`, ссылки, причины).

## Как использовать
- `architect` обязан **читать этот файл перед декомпозицией**, правкой плана и triage инцидентов.
- Находки добавляются **по факту** (разработка, ревью, проверка соответствия правилам, интеграционный прогон). Не превращать сюда срочные правки, если их нужно сделать в текущей задаче по согласованию.
- Любая запись должна быть проверяемой/конкретной: ссылки на файлы, символы, разделы `docs/gameDocs/rules.md` (`§…`), связанные `T-*`, команды/наблюдения.
- Процессные фрикции (неоднозначности, лишние поиски, потери на коммуникации) фиксируются в отчётах `docs/projectDocs/reports/` (разделы трения/ретро), а в техдолг попадают только если есть продуктовая/кодовая/документационная находка вне scope.

## Правила
- Формат записи: стабильный идентификатор **`TD-###`** (по возрастанию, **не переиспользовать**).
- Для каждой записи указывать: дату фиксации, контекст (какая задача/поток: `T-*`, декомпозиция, прогон сценария, wave, triage), источник (пути/символы/команды).
- Не менять `AGENTS.md` и `docs/gameDocs/rules.md` из-за задач техдолга без отдельного запроса.
- Закрытие: ставить статус `done` и указывать ссылку на `T-*`, MR/коммит (текст), дату и/или волну закрытия при применимости; `wontfix` — только с явной причиной.
- **Очистка/архивация:** после закрытия записи перенести её в `docs/projectDocs/tech-debt-archive.md` (рекомендуется) либо удалить из активного списка по согласованному решению процесса, сохранив `TD-*` и ключевые ссылки в архиве/истории. Активный раздел `## Записи` не должен накапливать закрытые элементы без решения.

## Статусы
- `open` — зафиксировано, не запланировано.
- `planned` — включено в `todo.md` (указать `T-*` или ссылку на пункт).
- `done` — устранено (перед переносом/очисткой указать ссылки и контекст закрытия).
- `wontfix` — осознанно не делаем (причина обязательна).

## Шаблон записи
```md
## TD-001 — Краткое название
- **Статус:** open | planned | done | wontfix
- **Дата:** YYYY-MM-DD
- **Контекст:** T-XX / декомпозиция / прогон сценария / wave / triage / …
- **Источник:** `путь/к/файлу`, символ/секция, команда/наблюдение
- **Описание:** что обнаружено (факты)
- **Риск / почему может выстрелить:** …
- **Предлагаемые действия:** …
- **Связи:** `docs/gameDocs/rules.md §…`, `T-*`, `docs/projectDocs/…`
- **Закрытие (для done/wontfix):** T-*, MR/коммит, дата/волна, причина (для wontfix)
```
