# Промпт: приём находки в техдолг (любая роль)

Роль: любая (`implementer`, `verifier`, `scenario-tester`, `rules-auditor`, `architect`, `orchestrator`).

## Когда использовать
Найдена проблема/риск **вне текущей задачи**, которую нельзя или нецелесообразно править сейчас.

## Что сделать
1. Проверить, нет ли похожей записи в `docs/projectDocs/tech-debt.md` (активные `open`/`planned`) и в `docs/projectDocs/tech-debt-archive.md`.
2. Подготовить запись по шаблону `tech-debt.md`: `TD-###` (следующий свободный номер, не переиспользовать), статус `open`, дата, контекст (`T-*`/wave/triage), источник (файлы/символы/команды), описание, риск, предлагаемые действия, связи (`docs/gameDocs/rules.md §…`, `T-*`).
3. Если находка связана с планом — указать, в какой волне/карточке логичнее закрыть.
4. При закрытии: `done` (или `wontfix` с причиной) + ссылка на `T-*`, MR/коммит (текст), дата/волна при необходимости. Активный список — в основном `open`/`planned`; `done`/`wontfix` переносятся в архив или очищаются по политике.
5. Процессные фрикции — в отчёты `docs/projectDocs/reports/` (трение/ретро), в `TD-*` — продуктовые/кодовые/док-находки вне scope.
6. `todo.md` не править (кроме `architect` в отдельной ветке по специальному запросу).

## Выход
Готовый блок markdown для вставки в `docs/projectDocs/tech-debt.md` или описание необходимых правок статуса.
