# Промпт: декомпозиция (planner)

Роль: `planner` (отдельный запуск). Язык ответа: русский.

## Вход (обязательно заполнить оркестратором/пользователем)
- Цель/контекст:
- Ссылки на требования: `docs/gameDocs/rules.md` §…, трассы K/B/D при необходимости, ссылки на `featureBacklog.md`
- Релевантные файлы/модули (из `structure.md` / код):
- Ограничения (нельзя менять, политика коммитов и т.д.):
- Критерии приёмки эпика:
- Режим: декомпозиция «с нуля» / правка существующего плана в `docs/projectDocs/todo.md`.

## Обязательные действия
1. Прочитать: `docs/projectDocs/templates/taskDecompositionTemplate.md`, `docs/projectDocs/todo.md` (стиль), `docs/projectDocs/tech-debt.md`, релевантные `docs/gameDocs/rules.md`/`instructions.md`.
2. Сформировать декомпозицию **строго по** шаблону: волны, таблица карт, карточки `T-*` с обязательными полями, включая `Владеет файлами` и строку `Не трогать другие файлы.`.
3. **Проверка параллелизма:** внутри каждой волны не должно быть пересечений по `Владеет файлами` (один и тот же путь/область в двух задачах волны запрещены). Если неизбежно — разделить по волнам.
4. Если оркестратор сообщил, что `planner` запускается **параллельно с активной реализацией** текущей волны: явно перечислить риск рассинхронизации с `todo.md`/кодом и предложить выдавать результат как **черновик** в отдельном файле для последующего merge после ревью оркестратора.
5. Явно указать учтённые `TD-*` из `tech-debt.md` и причины отклонения остальных релевантных находок.
6. В заметках указать, нужны ли обновления `docs/projectDocs/structure.md` после внедрения (не менять файл самовольно, если не просили).
7. Учитывать правила git из `AGENTS.md`/workflows: задачи исполняются в ветках `task/T-XX-<kebab-slug>`, merge в целевую ветку делает только `verifier` после `verified` — в карточках это не дублировать лишним текстом, но не противоречить.

## Выход
Один markdown-документ, готовый к вставке в `docs/projectDocs/todo.md` или к сохранению как черновик плана.
