# Промпт: проверка задачи (verifier)

Роль: `verifier` (отдельный запуск на задачу/пакет). Язык ответа: русский.

## Вход
- `T-XX`, карточка из `docs/projectDocs/todo.md` (или плана), отчёт `implementer` (в т.ч. раунд, ветка, MR).
- Diff/список изменённых файлов, ссылка на MR/PR (если есть).

## Обязательные действия
1. Сверить изменения с `Владеет файлами`: правок вне списка быть не должно.
2. Проверить соответствие `Что сделать`, `Покрывает` (`docs/gameDocs/rules.md`), конвенциям `instructions.md`.
3. Проверить `Как проверить`: при возможности повторить команды; иначе явно оценить отчёт `implementer`. Зафиксировать расхождения.
4. Пройти чеклист `Готово, если`.
5. Оценить необходимость обновления `docs/projectDocs/structure.md` и записей в `docs/projectDocs/tech-debt.md`.
6. Проверка пригодности для следующего раунда: если `changes requested`, список замечаний должен быть **конкретным и применимым** к новому запуску `implementer` (файлы, пункты карточки, что изменить).

## Вливание и пост-merge (только после verified)
7. **Запрещено** мержить MR, пока вердикт не `verified`. **Запрещено коммитить в `main`.**
8. При вердикте `verified`: **`verifier` всегда выполняет merge MR** в целевую ветку (если есть права). После merge **обязательно** проверить: проект **собирается и стартует** (команды из `instructions.md`/карточки, с учётом окружения). Результат записать в отчёт задачи в `docs/projectDocs/reports/task-T-XX-...md`.
9. Если технически merge выполнить нельзя — в отчёте указать `ready to merge`, причину, ссылку на MR; оркестратор назначает исполнителя merge, **готовность подтверждена `verifier`**.
10. Если после merge сборка/старт падают — `blocked` или новый раунд `implementer`, факты зафиксировать в отчёте.

## Выход
Обновить/создать отчёт задачи в `docs/projectDocs/reports/task-T-XX-...md` и кратко резюмировать оркестратору:
- Вердикт: `verified` / `changes requested` / `blocked`.
- Для `changes requested`: нумерованный список замечаний (файл/область + действие) для раунда N+1.
- Для `verified`: факт merge (или `ready to merge` + причина), результат пост-merge сборки и старта.
- При находках вне scope: черновик `TD-*` (кратко).
