## 2. Проверка на новые противоречия/пробелы, внесённые доработкой (в рамках scope)

Противоречий и blocker/high-пробелов, внесённых доработкой, **не обнаружено**.

Проверенные связки:
- `T_leg_back` (§4) согласован во всех точках использования: §4 Query (`deliveryMinute`, `expectedReplyAt`, ветка потери курьера `sentMinute + 2*T_leg + 30`) и §6 Report (`deliveryMinute = eventMinute + T_leg_back`). Триггеры `Report` — узловые события, поэтому выбор узла для `T_leg_back` однозначен. `pendingOrder`/смена приказа на ребре не создаёт конфликта: значение `T_leg_back` фиксируется на событие.
- Семантика `hold` (§5) не конфликтует с §3 (переход `intent → hold` с целью `v` после занятия узла) и с §7 (posture `defense`).
- Каденция recon (§6) согласована с §2 шаг 3 (проверка обнаружения/`ReconResult`), §5 `recon` (наблюдение из смежного узла) и §7 (recon из соседнего узла в бою не участвует). `edgePenalty` для recon-наблюдения через ребро согласован с формулой `p_detect`.
- Искажение recon согласовано: при `targetZone != null` `A = 0` (нет `+0.70`/`+0.15`), Шаг 2 (`A > 0`) не выполняется → неоднозначной ветки «recon ↔ move/hold» не возникает; при `targetZone == null` `A = 0.70`, и ветка `targetZone == null` Шага 2 обрабатывает recon определённо. Противоречия нет.
- Объявленное «вне scope» (§6) не противоречит §7 (метрики по приказам, а не по донесениям).
- StateScore (§7) полон и не пересекается с прочими разделами.

Наблюдения (low, не блокируют `passed`, вне строгого scope r5, рекомендация к будущему раунду/`TD`):
- `recon` не описывает движение к смежному узлу: буквальное чтение §5/§6 — юнит не двигается по приказу `recon`; при не-смежности наблюдение не идёт, и по истечении 30 мин формируется `ReconResult` confidence 1. Поведение вычислимо, но явное предложение «recon не инициирует движение и требует предварительного выхода в смежный узел» повысило бы однозначность. Замечание предсуществующее (с r3), доработкой r5 не внесено.
- Для простого графа выбор ребра наблюдения однозначен; при наличии кратных рёбер между узлами `edgePenalty` (road/offroad) не был бы однозначен. При допущении простого неориентированного графа (§2) — не проблема.
