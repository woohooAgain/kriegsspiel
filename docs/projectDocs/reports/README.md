# Отчёты (reports)

Каталог для структурированных отчётов оркестрации и выполнения задач.

## Что хранить
- **Отчёты по задачам**: `task-T-XX-<short-slug>.md` (один файл на задачу или на ключевой этап; см. шаблон ниже).
- **Отчёты по волнам**: `wave-<N>-report.md` (после завершения задач волны и wave-level тестирования).

## Шаблон: отчёт по задаче (`task-T-XX-...md`)
```md
# Отчёт задачи T-XX — <краткое имя>

- **T-XX:** …
- **Волна:** …
- **Ветка задачи:** `task/T-XX-<kebab-slug>`
- **Целевая ветка MR:** …
- **MR:** (ссылка/ID или «не создан» + причина)
- **Раунды implementer:** 1,2,… (кратко: что менялось по раундам)

## Выполнено (по пунктам «Что сделать»)
- …

## Изменённые/созданные файлы (только ownership)
- …

## Проверки (из «Как проверить»)
- Команда → результат (или «не выполнено: …»)

## Верификация (verifier)
- Вердикт: verified / changes requested / blocked
- Замечания/раунды: …
- Merge: выполнен verifier? дата/коммит или «ожидает»; post-merge сборка+старт: …

## Заметки / tech-debt
- TD-* или «нет»
```

## Шаблон: отчёт по волне (`wave-<N>-report.md`)
```md
# Отчёт волны Wave N — <название>

- **Дата:** …
- **Целевая интеграционная ветка / main:** …

## Задачи волны
| T-* | Статус (done/blocked/…) | Ветка | MR | Вердикт verifier | Примечание |
|-----|-------------------------|-------|----|------------------|------------|

## Параллелизм и ownership
- Кратко: какие T-* запускались параллельно, подтверждение отсутствия пересечений `Владеет файлами`.

## Post-merge проверки (после каждого merge в целевую ветку)
- T-XX: сборка (`…`) → …, старт (`…`) → … (кто выполнял: verifier)

## Wave-level интеграционное тестирование («запуск и игра»)
- Кто: `scenario-tester` / оркестратор
- Сценарии/шаги: …
- Результат: pass/fail, дефекты → T-* / TD-*

## Итоги
- Закрыто задач: …
- Открытые блокеры / TD-*: …
```
