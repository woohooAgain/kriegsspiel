# FS-022 — Линейка приказов для артиллерии

- **Статус:** blocked
- **Источник:** `docs/gameDocs/featureBacklog.md` #25 «Нет линейки приказов для артилерии»
- **Связанные правила:** `docs/gameDocs/rules.md §2` (юниты: полки/батальоны/артиллерия/разведка/штаб; параметры юнита; боезапас; `CombatEffective`-зависимые свойства), `§3` (ПРИКАЗ — одному юниту; курьеры; журнал; суперсессия), `§4` (закрытые слоты/намерения/ограничения/условия/действия/режимы; семантика слотов «Куда»; цена неоднозначности; конструктор ветвей; шаблоны), `§5` (четыре стадии приказа; понимание; исполнение; донесение), `§6` (туман войны; знание ≠ истина; разведка; `fact key`), `§7` (бой только при совместном нахождении/контакте в зоне; разрешение каждые 30 мин; геометрия контакта; сила/потери; расход боезапаса; `CombatEffective` требует `Ammo > 0`), `§9` (`escort`/груз/конвои — контекст расхода/перемещения, не прямой артиллерийский огонь), `§12` (инварианты: закрытые списки намерений/ограничений/условий/действий/режимов, семантика `§7`, детерминизм/replay/save-load; профиль меняет только перечисленные числовые параметры и явно разрешённые табличные функции).
- **Связанные артефакты:** `docs/gameDocs/featureSpecs/FS-007-composite-units.md` (`ready_for_decomposition`, приданная артиллерия как статическая связь; поддержка — обычный `support`; дальность/прицельный огонь/спецснаряжение — вне scope, backlog #8), `docs/gameDocs/featureSpecs/FS-008-complex-equipment-model.md` (`blocked`, дальность прицельного поражения, loadout/взрывчатка, Q1–Q8).
- **Владелец спеки:** analyst

## Цель и ценность
- Устранить продуктовый разрыв backlog #25: для артиллерийского юнита (`UnitType.Artillery`) игрок должен получать понятный и корректный набор приказов, соответствующий роли артиллерии, а не сталкиваться с отсутствием/неуместностью «линейки» приказов.
- Сохранить канонические инварианты: закрытые списки `§4`, семантика боя `§7` (контакт/совместное нахождение в зоне), знание ≠ истина `§6`, детерминизм/replay/save-load `§12`, симметрия сторон `§2`.

## Бизнес-поведение и сценарии

### Факты текущего состояния (код/канон)
- **Домен:** `UnitType.Artillery` существует (`Kriegsspiel.Core/Domain/Unit.cs`), юнит имеет `Ammo`; `CombatEffective` требует `Ammo > 0` (`§7`, `Unit.IsCombatEffective`).
- **Приказы:** закрытый список намерений `§4`/`OrderIntent` включает `Seize/Hold/Move/Recon/Support/Withdraw/Reserve/Occupy/Advance/Delay/Escort/Destroy/Block/Check/Guard`; ограничений — `NoZoneEntry/NoEngagement/NoRetreatBeyondZone/NoAmmoUse/NoWeaponDisplay`. Конструктор UI (`Kriegsspiel.Console/Commands/OrderBuilder.cs`) предлагает все `OrderIntent` любому выбранному юниту без фильтра по `UnitType`.
- **Бой:** `§7` разрешает бой только при совместном нахождении/контакте в зоне, тик 30 мин, сила по общей формуле; дальность прицельного поражения, огонь из соседней зоны, огневые задачи/подавление на дистанции, целеуказание по не-контактной зоне и отдельный расход боезапаса на огневую миссию в каноне не описаны.
- **FS-007:** приданная артиллерия использует обычный `support` (район/юнит), автоматического огня нет; дальность/прицельность/спецснаряжение — backlog #8 / вне scope FS-007.

### Интерпретация backlog #25 и решение analyst

**Решение:** backlog #25 трактуется как запрос на выделенную артиллерийскую линейку приказов, которая в полном смысле требует огневых/артиллерийских задач и, следовательно, новых механик/канона. Узкая интерпретация A (UI-фильтр существующих приказов) фиксируется как возможный in-canon fallback, но **не** объявляется достаточной реализацией #25 без подтверждения инициатора/`rules-auditor`. До уточнения канона спека остаётся `blocked`.

### Целевые сценарии (после снятия блокеров, для ориентира декомпозиции)
1. **Артиллерийский юнит получает релевантную линейку приказов.** При выборе `UnitType.Artillery` в конструкторе приказов игрок видит только допустимые/понятные для артиллерии задачи; недопустимые/неподдерживаемые варианты не вводят в заблуждение.
2. **Огневая задача по известной цели (если канон разрешит дистанционный огонь).** Игрок задаёт цель (зона/объект/направление/наблюдаемый контакт — по будущему канону), время/условия, ограничения по боезапасу; приказ проходит 4 стадии `§5`; результат/невозможность отражается в донесениях `§5`/`§6`.
3. **Невозможность/ограниченность выполнения.** При отсутствии боезапаса, отсутствии целеуказания/знания, нарушении ограничений, потере связи/уничтожении исход детерминирован и наблюдаем через `ReportKind.Impossible`/донесения/разбор.
4. **Туман войны.** Целеуказание и эффект огня не раскрывают скрытую истину о противнике; игрок получает только допустимое знание/донесения/наблюдения.
5. **Расход и снабжение.** Огневая задача расходует боезапас по канонической модели; при нуле боезапаса поведение соответствует `§2`/`§7`/будущему канону.
6. **Детерминизм/replay/save-load.** Те же seed/ввод/снимок воспроизводят выдачу, понимание, исполнение, расход и результаты артиллерийских приказов.

## Scope / Non-scope
- **In scope (после снятия блокеров):**
  - Продуктовое определение «линейки приказов для артиллерии» (UX + каноническая семантика).
  - Каноническое решение: только фильтр существующих `§4` намерений для артиллерии, или новые огневые намерения/задачи/цели/ограничения.
  - Если новые огневые приказы: модель целеуказания/знания цели, дистанции/зоны воздействия (или явный отказ от дистанции), расхода боезапаса, времени подготовки/исполнения, проверки применимости, эффектов/исходов, донесений/разбора.
  - Валидация, UI конструктора приказов, AI/LLM-контракт приказов, persistence/replay, тесты детерминизма.
- **Out of scope:**
  - Реализация кода, декомпозиция в `T-*`, правки `todo.md`, правки `docs/gameDocs/rules.md`/`AGENTS.md`.
  - Полная модель сложного снаряжения/loadout/взрывчатки (backlog #8, `FS-008`) — кроме явных точек пересечения, которые должны быть согласованы.
  - Баланс урона, таблицы дальности/калибров, историческая достоверность артсистем.
  - Новые типы юнитов/формирований сверх текущего `UnitType.Artillery` (кроме канонического решения).
  - Сетевой/графический UI.

## Заключение rules-auditor

**Вердикт:** `blocked` для полного закрытия backlog #25 как «линейки артиллерийских/огневых приказов». Под текущим каноном дистанционный огонь/огневые задачи не выводятся; допустим только узкий in-canon fallback (фильтр/подписи существующих intents `§4`) после явного подтверждения продукта, что это удовлетворяет #25.
