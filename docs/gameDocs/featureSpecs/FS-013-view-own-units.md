# FS-013 — Просмотр своих отрядов

- **Статус:** ready_for_decomposition
- **Источник:** `docs/gameDocs/featureBacklog.md` #16 «Нельзя посмотреть свои отряды»
- **Связанные правила:** `docs/gameDocs/rules.md §2` (юнит: сила, боеготовность, мораль, усталость, боезапас, текущий район; открытые характеристики командиров и выучка; скрытые боевой опыт и текущее знание командира; противник не виден игроку напрямую), `§3` (действия в штабе, `ЗАПРОС`, `ЖУРНАЛ`, курьеры и статусы приказов), `§4-5` (приказ, четыре стадии, эффективный приказ, четыре поля донесения), `§6` (истина vs знание, донесения, event/delivery, уверенность, противоречия, наблюдение своих и противника), `§12` (детерминизм, сохранение/воспроизведение). Связанный артефакт: `FS-005` (свои подразделения в контексте карты). Спека не изменяет канон правил.
- **Владелец спеки:** analyst

## Цель и ценность
- Дать начальнику штаба отдельное действие просмотра своих подразделений: компактный список и карточка с идентификацией, состоянием и приказом, чтобы не удерживать состав и статусы в памяти и не рыскать по журналу/донесениям.
- Сохранить различие «истина симуляции» и «знание игрока» (`rules.md §6`): экран фильтрует только свои силы и не становится новым каналом раскрытия скрытой истины — ни своей динамики, ни противника.
- Снизить риск ошибочного управления: в карточке явно видны источник и давность сведений, а отсутствующие данные не подменяются нулями или фактами.

## Бизнес-поведение и сценарии

### 1. Факты текущего состояния (без догадок)
- `Kriegsspiel.Console/Startup/GameLoop.cs`: в меню штаба есть `ОБСТАНОВКА`, `КАРТА`, `ПРИКАЗ`, `ЗАПРОС`, `ЖУРНАЛ`, но нет действия просмотра своих отрядов.
- `SituationCommand.cs` показывает знание по зонам, противоречия и доставленные донесения; `MapRenderer.cs` — карту знания по зонам. Перечня/карточек своих юнитов нет.
- `QueryCommand.cs` выбирает адресата из `state.Units` по `Faction.Blue` и уже показывает в консоли `Name`, `Id`, `Type`, `LocationZoneId`; `OrderBuilder.cs` делает то же для адресата приказа. Это существующий UI-контекст управления своими силами, а не новая механика FS-013.
- `Kriegsspiel.Core/Domain/Unit.cs` содержит истинные `Strength`, `Readiness`, `Morale`, `Fatigue`, `Ammo`, `LocationZoneId`, `EffectiveOrder`, `Experience`, `CommanderLost`, `Concealed`, скрытые векторы внимания/движения и т.д. `PlayerKnowledge` хранит знание по зонам и `fact key`, но не готовых карточек юнитов. `Order`/`EffectiveOrder` и `JournalRenderer` содержат отданный приказ и его журнальные статусы.
- Текущий `GameStateFactory` создаёт пустой `PlayerKnowledge`; это отдельная проблема инициализации знания (backlog #18), а не часть FS-013. Новый экран обязан корректно работать с «нет данных».

### 2. Экран «СВОИ»
- В штабном меню появляется отдельное действие просмотра своих отрядов с возвратом в меню. Экран доступен в те же моменты, что и другие штабные действия (между отрезками, пока часы не идут).
- Экран показывает **только подразделения своей стороны** (в текущей модели — `Faction.Blue`), включая штаб, если он присутствует в сценарии. Список стабильно упорядочен (например, штаб первым, затем по типу/Id/имени) и остаётся читаемым при большом числе юнитов: компактная сводка/фильтрация/постраничность или эквивалентная навигация к карточке.
- Список — вход в карточку. В списке отражаются: идентификация, зона/контекст, короткое состояние по последнему известному донесению/приказу, признак отсутствия данных и давность обновления. Полный набор полей и их источники раскрываются в карточке.

### 3. Карточка своего отряда: набор полей и источники
| Поле | Что показывается | Источник / ограничение |
|---|---|---|
| Идентификация | `Id`, имя, тип подразделения, принадлежность к своей стороне; при наличии — открытая брифинговая информация (черты командира, выучка, флаг устойчивости к потере управления) | Открытая информация `§2` и уже доступный игроку перечень своих юнитов в `ПРИКАЗ`/`ЗАПРОС`. Боевой опыт не показывается (`§2`). |
| Зона / местоположение | Текущая зона в том же контексте управления, который уже используется при выборе адресата (`LocationZoneId` в текущем консольном UI); при наличии доставленного донесения с более поздним временем — значение из донесения с пометкой источника и времени | По прецеденту `FS-005`: свой юнит доступен для командования; не расширять на противника. Не является новым правилом видимости. |
| Сила | Последнее известное значение силы/примерных потерь из доставленного донесения или ответа на запрос | Только из доставленного знания с event/delivery/источником/уверенностью (`§5-6`). Не брать напрямую `Unit.Strength`. Нет данных → «нет данных». |
| Боеготовность | Последнее известное значение боеготовности из доставленного донесения/ответа | Только из доставленного знания (`§6`). Не брать напрямую `Unit.Readiness`. |
| Боезапас | Последнее известное значение боезапаса из доставленного донесения/ответа | Только из доставленного знания (`§6`). Не брать напрямую `Unit.Ammo`. |
| Приказ | Последний приказ штаба: `Id`/версия, намерение и цель, минута отдачи, доставка/принятие/потеря/суперсессия по журналу; отдельно — подтверждённое доставленным донесением понимание приказа отрядом | Открытые действия игрока и журнал `§3`, `§5`. `Unit.EffectiveOrder` как скрытая истина понимания не показывается; если приказ не подтверждён — «не подтверждено», а не «исполняется». |
| Происхождение и свежесть | Для каждого динамического поля: источник, минута события, минута доставки/обновления, уверенность 0–3; при противоречии — все версии | `§6`: знание устарело/неполно/искажено/противоречиво; «нет данных» отличается от «пусто/нет сил»; `QuerySilence` не является фактом. |

- Динамические поля (сила, боеготовность, боезапас, понимание приказа) обновляются **только доставленными** донесениями и ответами на запросы. Пока данных нет, показывается явное «нет данных»; нули, значения из истины симуляции и догадки запрещены.
- Если доставленные донесения дают разные версии по одному `fact key`, показываются все версии с источниками и уверенностью; уверенность снижается по правилу противоречия `§6`. Игрок видит знание, а не «правильную» версию.
- Мораль, усталость, боевой опыт, скрытые векторы внимания/движения, маскировка, пленение и т.п. не вводятся как отдельные числовые поля карточки. Они могут присутствовать только в тексте/фактах доставленного донесения с его происхождением.

### 4. Запрет раскрывать противника
- Новый экран не перечисляет вражеские/нейтральные юниты, не показывает их `Id`, тип, зоны, силу, боеготовность, боезапас, приказы, `EffectiveOrder` или иные поля `Unit`/`GameState` для противника.
- Информация о противнике остаётся только в существующих представлениях знания: `ОБСТАНОВКА`/`КАРТА` (состояние зон, кем по донесениям, уверенность, время, противоречия), `ЖУРНАЛ` и доставленные донесения/ответы на запросы (`§2`, `§6`). Если текст доставленного донесения упоминает противника, он показывается как содержание донесения с источником и уверенностью, а не как структурированная истина в карточке своего отряда.
- Своя карточка не должна косвенно раскрывать противника через сравнение с скрытым состоянием (например, «противник знает о нашем приказе», «наш отряд незаметно стоит рядом с врагом»).

### 5. Сценарии
1. **Старт отрезка, донесений нет:** список своих отрядов доступен; карточка показывает идентификацию, зону из UI-контекста и «нет данных» для силы/боеготовности/боезапаса/понимания приказа; приказ — только уже отданный и зафиксированный в журнале.
2. **Доставлен статус/ответ на запрос:** карточка обновляет соответствующие поля из донесения с минутой события, минутой доставки, источником и уверенностью; старые значения не выдаются за актуальные.
3. **Приказ отдан, но не доставлен/не подтверждён:** в карточке виден статус из журнала; не утверждается, что отряд исполняет приказ. Доставка/принятие/суперсессия отражаются по журналу `§3`.
4. **Противоречивые донесения или молчание:** показываются все версии с уверенностью; `QuerySilence` фиксируется как «нет ответа в срок», не как «факта нет» и не как нулевое состояние.
5. **Много отрядов:** игрок быстро находит нужный отряд в сводке и открывает карточку; экран не превращается в один перегруженный список.
6. **Рядом противник:** вражеские юниты и их скрытые параметры в «СВОИ» не попадают; доступ к ним только через знание/донесения в штабных экранах.

## Scope / Non-scope
- **In scope:**
  - Новый экран/действие просмотра своих отрядов в консоли: список + карточка с фиксированным набором полей из раздела 3.
  - Использование уже доступной игроку информации: открытой брифинговой (`§2`), журнала приказов/запросов (`§3`) и доставленного знания (`§5-6`).
  - Явная маркировка источника, времени события/доставки и уверенности; обработка «нет данных», противоречий и молчания по `§6`.
  - Запрет вывода противника и скрытой истины в новом экране; сохранение читаемости при росте числа отрядов.
  - Проверяемые сценарии и регрессия существующих экранов `ОБСТАНОВКА`, `КАРТА`, `ЖУРНАЛ`, `ЗАПРОС`, `ПРИКАЗ`.
- **Out of scope:**
  - Изменения `docs/gameDocs/rules.md`, `AGENTS.md`, `todo.md`, `featureBacklog.md`, канона видимости, формул и игрового баланса.
  - Новые правила накопления знания, генерации донесений, расчёта потерь/боезапаса/боеготовности, изменения курьерной модели.
  - Прямой показ истинных `Unit.Strength/Readiness/Ammo/EffectiveOrder` и скрытых полей противника; новые карточки вражеских юнитов.
  - Переработка конструктора приказов, карты, донесений и AAR сверх минимально необходимой связки/переиспользования; исправление backlog #18 (пустая инициализация знания) и #15 (возврат из приказа) как отдельные задачи.
  - Реализация FS-001 (командиры), FS-005 (масштабируемая карта), локализация, AI, сохранение/replay как самостоятельные изменения.

## Разрешённые неоднозначности и решения
- **Вопрос:** Можно ли показывать силу/боеготовность/боезапас прямо из текущего состояния `Unit`, если это свои войска?
  - **Решение:** Нет. Динамические поля карточки — только доставленное знание с происхождением; при отсутствии данных — «нет данных». Идентификация, открытые черты/выучка и уже используемый в `ПРИКАЗ`/`ЗАПРОС` зональный контекст своих юнитов остаются доступными как открытая/уже показанная информация.
  - **Основание:** `§2` открывает характеристики командиров и выучку, но не текущие числовые потери/ресурсы; `§6` запрещает показывать истину и требует обновления доставленными донесениями; `FS-005` допускает свои силы в объёме управления и карты без раскрытия скрытой истины о противнике.
- **Вопрос:** Что считать «приказом отряда» в карточке?
  - **Решение:** Отданный приказ штаба и его статус по журналу. Эффективный приказ в понимании отряда — только если он стал содержимым доставленного донесения; иначе «не подтверждено». Сырой `Unit.EffectiveOrder` не показывается.
  - **Основание:** `§3` (журнал и статусы доставки), `§4-6` (эффективный приказ, донесения, знание ≠ истина, наблюдатель не видит текст приказа/намерение).
- **Вопрос:** Можно ли показывать текущую зону своего отряда, если в коде это поле истины симуляции?
  - **Решение:** Да, в объёме уже существующего UI-контекста выбора адресата (`QueryCommand.cs`, `OrderBuilder.cs`) и на прецедент `FS-005`; значение помечается как контекст управления, а не как новое правило видимости. Для противника такой доступ не создаётся.
  - **Основание:** `FS-005` (свои силы для командования и карты), `§2` (текущий район — атрибут юнита; противник не виден напрямую).
- **Вопрос:** Как обрабатывать отсутствие сведений, молчание и противоречия?
  - **Решение:** «Нет данных» — отдельное состояние; `QuerySilence` — «нет ответа в срок», не факт; противоречащие версии показываются все — с источником, минутами события/доставки и уверенностью. Пустые/нулевые подстановки запрещены.
  - **Основание:** `§6` (`нет данных` vs `пусто`, метки времени, снижение уверенности, обе версии), `§3` (`QuerySilence`).
- **Вопрос:** Должен ли экран показывать противника для сравнения?
  - **Решение:** Нет. Противник остаётся только в знании/донесениях существующих экранов.
  - **Основание:** `§2`, `§6`, `FS-005`.
- **Вопрос:** Требуются ли изменения канона или эскалация к `rules-auditor`?
  - **Решение:** Нет. Решение — представление уже доступной информации без изменения правил видимости; новая механика не вводится.
  - **Основание:** сопоставление `§2`, `§3`, `§5`, `§6` и текущего кода/артефакта `FS-005`.

## Критерии готовности к декомпозиции / приёмки (бизнес)
- [ ] В штабном меню доступно действие просмотра своих отрядов с возвратом в меню; список содержит только свои подразделения и не содержит противника/нейтральных.
- [ ] Список компактен и пригоден для навигации при увеличенном числе отрядов; из списка открывается карточка одного отряда.
- [ ] Карточка содержит фиксированный набор: идентификация, зона/местоположение, сила, боеготовность, боезапас, приказ, происхождение/свежесть.
- [ ] Сила, боеготовность и боезапас заполняются только из доставленного знания; при отсутствии данных показывается «нет данных», а не значения `Unit` или нули.
- [ ] Приказ в карточке берётся из журнала со статусом доставки/принятия; понимание отрядом показывается только по доставленному донесению; сырой `EffectiveOrder` не раскрывается.
- [ ] Для каждого динамического поля видны источник, минута события, минута доставки/обновления и уверенность; противоречия показываются всеми версиями; `QuerySilence` не трактуется как факт.
- [ ] Экран не использует и не показывает скрытые поля противника; вражеские сведения встречаются только как содержание доставленного донесения с его происхождением.
- [ ] Существующие экраны и симуляция не меняются: детерминизм, журнал, знание и сохранение работают как прежде (`§12`); scope/non-scope зафиксированы, правки `rules.md` не требуются.
