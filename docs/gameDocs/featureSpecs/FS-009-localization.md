# FS-009 — Локализация

- **Статус:** draft
- **Источник:** `docs/gameDocs/featureBacklog.md` #9 «Локализация»
- **Связанные правила:** `docs/gameDocs/rules.md §3` (команды штаба `ОБСТАНОВКА/КАРТА/ПРИКАЗ/ЗАПРОС/ЖУРНАЛ/ВРЕМЯ +30` как интерфейс игрока), `§5`/`§6` (донесения: 4 поля, источник, уверенность, противоречия/«нет данных»/«пусто» — семантика не меняется), `§10–11` (AAR/метрики и журнал ссылаются на действия/типы событий), `§14` (пример с названными командами). Прямых правил локализации в `rules.md` нет.
- **Владелец спеки:** analyst

## Цель и ценность
- Дать возможность запускать и проходить игру на выбранном языке интерфейса без изменения игровых правил, механик, таймингов и исходов симуляции.
- Сохранить текущее русскоязычное поведение/тексты как доступный вариант по умолчанию (обратная совместимость восприятия для текущих игроков и существующих материалов).
- Подготовить основу для добавления новых языков без правок доменной логики симуляции.

## Текущее состояние (наблюдаемые факты)
- UI консоли содержит жёстко заданные русские строки: меню/команды и метки в `Kriegsspiel.Console/Startup/GameLoop.cs` (в т.ч. `ОБСТАНОВКА/КАРТА/ПРИКАЗ/ЗАПРОС/ЖУРНАЛ/ВРЕМЯ +30`, `СОХРАНИТЬ/ЗАГРУЗИТЬ/ВЫЙТИ`), заголовки/статусы/ячейки в `Kriegsspiel.Console/Commands/*` и рендерерах (напр. `SituationCommand.cs`, `ReportRenderer.cs`: подписи `НЕВОЗМОЖНО/Молчание/нет данных/пусто`, подписи видов донесений, форматирование вывода).
- Тексты донесений шаблонизируются данными `Content/reports.json` (русские шаблоны и плейсхолдеры) и формируются `ReportFactory`/рендерингом.
- Игровой контент сценариев (`Content/scenarios/*.json`) содержит человекочитаемые строки (названия сценария/зон/объектов/юнитов и т.п.) на русском.
- Канонические правила `docs/gameDocs/rules.md` и проектная документация — на русском (конвенция: «язык документации и игровых текстов — русский», `docs/projectDocs/instructions.md`).
- Инфраструктуры i18n/l10n (ресурсные файлы, каталоги переводов, выбор культуры) в репозитории не обнаружено (факт на момент анализа).

## Бизнес-поведение и сценарии
1. **Выбор языка:** игрок может выбрать язык интерфейса (через настройку/конфигурацию запуска и/или пункт/параметр, определяемый при декомпозиции) до начала или при запуске сессии. Выбранный язык применяется к пользовательскому тексту UI в рамках поддерживаемых локалей.
2. **Язык по умолчанию и fallback:** при отсутствии явного выбора используется язык/локаль по умолчанию (совместимый с текущим русским UI). При отсутствии перевода конкретной строки/шаблона используется детерминированный fallback (предпочтительно на язык по умолчанию/базовый) — без падений и без потери ключевой информации (факт, время, источник, уверенность для донесений не должны пропадать из-за отсутствия перевода).
3. **Локализация UI:** локализуются отображаемые элементы интерфейса — меню и подписи команд, заголовки экранов, подписи полей/таблиц/статусов, служебные сообщения (ошибки ввода, подтверждения сохранения/загрузки, завершение сценария и т.п.), метки видов донесений и состояний знания («нет данных»/«пусто»/противоречие и др.), при сохранении их смысла.
4. **Локализация текстов донесений:** шаблоны/тексты, формируемые для игрока (в т.ч. из `reports`/шаблонов), отображаются на выбранном языке при наличии переводов; подстановка игровых параметров (время, источник, уверенность, юнит/зона/потери и т.д.) корректна для целевого языка.
5. **Семантика и инварианты:** локализация затрагивает только представление (текст). Не меняются: правила и исходы симуляции, детерминизм при одинаковых входах/seed, канонические идентификаторы (ID зон/юнитов/событий, `ReportKind`, `fact key`, поля контрактов), числовые значения, тайминги, 4 поля донесения и трактовка уверенности.
6. **Контент сценариев:** человекочитаемые строки сценарного контента (названия и описательные тексты, поставляемые с игрой) доступны на выбранном языке в объёме, определённом поддержкой контента для этой локали (см. открытые вопросы по scope/формату).
7. **Несовместимость выбора:** если запрошена неподдерживаемая локаль, система использует fallback/язык по умолчанию и сообщает об этом понятным образом (без скрытого изменения механик).

## Scope / Non-scope
- **In scope (цель фичи):**
  - Механизм внешнего хранения и подстановки переводимых строк UI (меню, экраны `ОБСТАНОВКА/КАРТА/ПРИКАЗ/ЗАПРОС/ЖУРНАЛ`, действия времени/сохранения/загрузки/выхода, сообщения и ошибки) с поддержкой нескольких локалей и fallback.
  - Локализация отображаемых текстов/шаблонов донесений и связанных меток (виды, статусы, сигналы) при неизменной семантике и полноте обязательных полей.
  - Выбор/конфигурация локали и поставка русского набора как базового/совместимого; возможность добавления новых языков пакетом переводов/данных без изменения игровой логики.
  - Требования к проверяемости: переключение локали не влияет на состояние симуляции/сохранения смыслов, ключевые элементы (время, числа, уверенность, ID/факты) остаются корректными.
- **Out of scope (для данной спеки/без отдельных решений):**
  - Изменение канонических правил игры, формул, таймингов, контрактов домена/событий (`docs/gameDocs/rules.md` — только отдельным запросом с подтверждением).
  - Перевод/редакция `docs/gameDocs/rules.md`, `AGENTS.md` и прочей проектной/игровой документации (отдельная документальная задача/запрос; не часть runtime-локализации).
  - Автоматический машинный перевод.
  - Изменение детерминизма симуляции, формата сохранений ради перевода (кроме явно согласованных совместимых метаданных, если потребуются — решается отдельно) и внутриигровых ID.
  - Локализация пользовательского моддинга/произвольных сторонних сценариев сверх определённого формата поставки (если не будет решено в scope контента).
  - Голос/озвучка и иные аспекты backlog #6 (аудио) — не входят.

## Разрешённые неоднозначности и решения
| Вопрос | Решение | Основание |
|---|---|---|
| Влияет ли локализация на механику/исходы? | Нет. Локализуется только представление (текст UI/шаблонов/отображаемый контент). Идентификаторы, события, расчёты, детерминизм, 4 поля донесения и семантика уверенности/`fact key` неизменны. | `rules.md §5–6, §12` (детерминизм, знание≠истина, структура донесений); цель фичи — язык, не геймплей. |
| Что с текущим русским языком? | Русский сохраняется как поддерживаемая локаль и базовый набор строк (совместимость с текущим поведением). | Текущее состояние репозитория/контента целиком на русском; минимизация регрессий. |
| Что делать при отсутствии перевода? | Детерминированный fallback на базовую/дефолтную локаль для отсутствующих ключей; отсутствие перевода не должно скрывать факт/время/источник/уверенность/критические сигналы. | Требование надёжности UI и сохранения смысла донесений (`§6`). |
| Соответствие команд UI канону `rules.md` | Семантика действий `§3` (обстановка/карта/приказ/запрос/журнал/шаг времени) сохраняется. Отображаемые подписи команд могут быть локализованы; внутренняя привязка должна однозначно соответствовать тем же действиям. Текст канона `rules.md` на других языках не создаётся в рамках runtime-фичи (см. non-scope/эскалацию). | `rules.md §3, §11, §14` фиксируют действия/метрики; изменение формулировок канона — отдельный запрос. Решение о допустимости/способе локализованного ввода команд — см. открытые вопросы. |
| Локализация сценарного контента | В рамки фичи включается требование отображать поставляемый с игрой контент на выбранном языке **при наличии** соответствующих переводов/вариантов; конкретный формат хранения и объём переводимого контента (какие поля, все ли сценарии) фиксируются при уточнении scope. | Контент уже содержит пользовательские строки (`Content/scenarios/*`); без решения формата нельзя гарантировать полноту — вынесено в блокеры/вопросы. |
| Язык LLM-нарратора/доктрины (если включены) | В MVP-спеке не задаётся отдельно: локализация затрагивает детерминированный UI/шаблоны; язык генерируемого LLM-текста и промптов — отдельное согласование (зависимость от контракта `rules.md §2`, профиля). | LLM — опциональный слой поверх фактов (`§2`), контракт языка не описан в backlog/правилах. |

## Критерии готовности к декомпозиции / приёмки (бизнес)
- [ ] Зафиксирован набор целевых локалей (минимум: дефолтная ru и перечень дополнительных) и правило выбора/fallback; определён источник конфигурации локали.
- [ ] Зафиксирован scope переводимых артефактов: UI-строки, шаблоны донесений (`reports`), системные сообщения; и отдельно — сценарный контент (какие поля/файлы/сценарии, формат поставки переводов).
- [ ] Определено поведение команд ввода: допускается ли локализованный ввод/алиасы команд при сохранении канонической семантики действий, либо отображение локализовано при фиксированном/каноническом наборе токенов (согласовано с `rules.md §3, §11`).
- [ ] Определены правила fallback, обработки отсутствующих/неполных переводов и отображения недоступной локали (без потери обязательных полей донесений).
- [ ] Подтверждено, что локализация не меняет симуляцию/детерминизм/ID/контракты; заданы проверяемые сценарии (переключение локали, полнота ключевых экранов и видов донесений, корректность подстановок).
- [ ] Согласован объём поставки на первый инкремент (MVP: UI+донесения; контент — в каком объёме) и критерий готовности переводов.

## Примечания для architect
- **Границы ответственности:** локализация — слой представления/контента; доменная модель, `Report`/`ReportKind`/`fact key`, `Clock`, RNG и расчёты не зависят от выбранного языка. Внутренние канонические ключи/ID — не источник отображаемого текста.
- **Затрагиваемые области (ориентир):** `Kriegsspiel.Console` (меню/команды/рендереры/сообщения) — основной потребитель строк; `Content/reports.json` и загрузка/фабрика донесений; возможно `Content/scenarios/*` и `ContentLoader/ScenarioBundle` при локализации контента; `FrictionTable`/профиль — не для текстов, но конфигурация языка может потребовать отдельного источника (уточнить в декомпозиции). Тесты, ассертящие русские строки/UI, потребуют адаптации под механизм локализации/дефолтную локаль.
- **Риски:** расхождение отображаемых подписей команд с текстом `rules.md §3,§11` при локализованном UI (нужна согласованность семантики/алиасов); неполные переводы, ломающие читаемость критических сигналов (молчание/невозможно/противоречие); подстановка параметров с учётом грамматики (плюрализация/порядок) — требование к формату строк; кодировки/шрифты консоли для нелатинских алфавитов.
- **Трассировка:** backlog #9 → данная FS. Декомпозицию в `T-*` не выполнять в рамках работы analyst; `todo.md` не менять. При появлении продуктовых решений по вопросам 1–5 спеку обновить до `ready_for_decomposition` с `Открытые вопросы: Нет`.
