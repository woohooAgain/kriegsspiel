## Связь со спеками (process, новые артефакты)
Для новых фич, берущихся в проработку после изменения процесса: `analyst` готовит бизнес-спеку `docs/gameDocs/featureSpecs/FS-*.md` и доводит её до `ready_for_decomposition` перед декомпозицией `architect`. При необходимости добавлять ссылки вида `→ FS-<id>` к пунктам backlog. Существующие пункты без спек остаются валидными идеями (обратной силы нет).

## Владелец и формат новых записей (`BL-*`)
- **Caretaker/groomer:** `analyst` (триаж, grooming, перевод идеи в `FS-*`). Добавлять идею в статусе `idea` может любой (человек/роль).
- **`architect`** потребляет фичи через `FS-*`, не через сырой backlog.
- **Обратной силы нет:** пункты 1..31 не переписываются. Для новых идей — структурированная запись (ID присваивается при касании; не переиспользовать).
- **Анти-дублирование:** у записи один «дом»; между артефактами только ссылки (`BL-### ↔ FS-* ↔ T-*`), без копирования тела. Маршрутизация — `docs/projectDocs/workflows/README.md`.

```md
## BL-### — <краткое имя>
- **Тип:** feature | improvement-idea
- **Статус:** idea | in_spec (FS-*) | planned (T-*) | done | wontfix
- **Дата/источник:** YYYY-MM-DD / кто/ref
- **Идея/ценность:** …
- **Заметки для analyst:** контекст, ограничения, сценарии, вопросы
- **Связи:** FS-*, T-*, rules §…
```
